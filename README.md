# 제조 공정 품질 Risk Monitoring

생산라인을 다 지난 제품마다 공정 기록으로 불량 위험 순위를 매겨, 품질 담당자가 추가로 확인할 제품을 위험한 것부터 고를 수 있게 하는 분석. 공정 초반에 미리 걸러 내는 조기 경보는 아님(2절 ④).

쓸 수 있는 곳과 쓰면 안 되는 곳, 숫자의 한계는 [`MODEL_CARD.md`](MODEL_CARD.md) 에 모았음. 결과와 판단 과정만 짧게 보려면 [`docs/PORTFOLIO.md`](docs/PORTFOLIO.md) 를 읽으면 됨.

핵심 질문은 "불량을 맞힐 수 있나"가 아니라 **"오늘 추가로 전체의 1%를 더 볼 수 있다면 어느 1%를 볼 것이며, 그러면 불량의 몇 %를 잡게 되나"** 임.

> **진행 상태 (2026-10-20)** — **실제 데이터로 Week 0~5(변환·데이터 이해·모델·평가·조기예측·오탐미탐·공정 기여도·그림·화면)를 끝냈고, Week 6에서 새 폴더 재현 실행, 모델카드, 대표 숫자의 하루 단위 재측정과 95% 구간, 포트폴리오 페이지까지 마치고 공개했음.** 결과 요약은 2절, 대표 그림은 `reports/figures/00_검사물량_포착률.png`.

## 1. 데이터 준비

Bosch Production Line Performance (Kaggle, 2016) 데이터를 씀. **이 데이터는 Kaggle 로그인과 대회 규정 동의가 있어야 받을 수 있어서 자동화할 수 없음.** 데이터는 저장소에 포함되어 있지 않으므로 각자 받아야 함(3절).

2. **규정에 동의**함 (`I Understand and Accept`). 동의하지 않으면 API로도 다운로드가 막힘

### Week 2~4 결과 요약 (시험 구간 236,750대, 불량 964건)

**① 대표 결과 — 검사 물량 대비 포착률**

| 검사율 | 검사 대수 | 포착 불량 | 포착률 | **무작위 대비** |
|---|---|---|---|---|
| 0.5% | 1,184 | 95 | 9.85% | **19.7배** |
| 1% | 2,368 | 111 | 11.51% | **11.5배** |
| 5% | 11,838 | 152 | 15.77% | 3.2배 |
| 10% | 23,675 | 208 | 21.58% | 2.2배 |
| 100%(전수) | 236,750 | 964 | 100% | 1.0배 |

검사율 1% 포착률의 95% 구간은 8.6~15.4%임(하루 묶음 블록 부트스트랩, `T_부트스트랩_구간.csv`). 이 표는 시험 구간 전체를 한 묶음으로 보고 상위 N%를 자른 것이고, 하루 단위로 잘라도 1%에서 106건으로 구분되지 않았음(③).

무작위 표본검사는 정의상 검사율 = 포착률이므로, 무작위 대비 배수가 "같은 인원으로 몇 배 더 잡는가"임.

**② 착수 전 예상(20~35%)의 절반임. 원인은 시간 분할이고 결함이 아님**

| 조건 | PR-AUC | 포착률@1% | 최종 대비 (PR-AUC 기준) |
|---|---|---|---|
| 시간 분할 + 누설 배제 (**최종**) | 0.0148 | 11.51% | 1.0배 |
| + Id 순서 누설 | 0.0329 | 15.04% | 2.2배 |
| + 무작위 분할 | 0.1332 | 25.89% | 9.0배 |
| + 둘 다 | 0.1400 | 27.08% | 9.4배 |

배수는 PR-AUC 기준임. 검사율 1% 포착률로 보면 Id 순서 누설은 약 1.3배(15.04 ÷ 11.51), 무작위 분할은 약 2.2배(25.89 ÷ 11.51)임. 표의 PR-AUC 는 sklearn `average_precision_score`(AP)이고 저장 파일 열 이름만 `PR_AUC` 로 남아 있음. 같은 데이터·모델·입력에서 분할만 무작위로 바꾸면 PR-AUC가 9배 높게 나옴. 단 무작위 분할은 시험셋 불량률도 0.41%에서 0.58%로 달라지고 PR-AUC 의 바닥값이 불량률이라, 불량률로 나눠 비교하면 약 6.3배임(`T_분할x입력_교차.csv`). 구간별 불량률이 학습 0.730% / 검증 0.308% / 시험 0.407%로 공정 상태가 기간마다 달라서임. 조기 종료(라운드를 7배로 늘리면 오히려 나빠짐)와 입력 부족(공정 파생 65개만으로 원시 968개와 같은 성능)은 원인이 아님을 확인함. 공개된 Bosch 결과 대부분이 무작위 분할이라 우리 숫자가 낮아 보이지만, 과거로 학습해 이후를 판정하는 운영 조건에 맞는 숫자는 이쪽임.

**③ 점수 문턱값을 고정하면 검사 물량이 2배 가까이 넘침**

| 목표 검사율 | 검증에서 정한 점수 문턱값을 그대로 쓰면 | 시험 구간 안에서 상위 N%를 다시 자르면 |
|---|---|---|
| 1% | 1.75% (1.75배) | 1.00% |
| 3% | 5.94% (1.98배) | 3.00% |
| 5% | 9.68% (1.94배) | 5.00% |

오른쪽 열은 시험 구간 전체(236,750대)를 한 묶음으로 보고 그 안에서 상위 N%를 자른 것이라 정의상 목표와 같음. ①의 대표 숫자도 이 방식임. 정답을 본 것은 아니지만 실제 현장은 5개월치를 다 모은 뒤 순위를 매기지 않으므로, 운영 단위로 다시 쟀음(`tools/batch_alert_rate.py`, 검사율 1%).

| 운영 방식 | 실제 검사율 | 포착 불량 | 같은 대수를 전체 순위로 뽑았다면 |
|---|---|---|---|
| 전체 묶음 상위 1% (①의 대표 숫자) | 1.00% | 111 | 111 |
| 하루가 끝나면 그날 안에서 상위 1% | 1.03% | 106 | 111 |
| 교대가 끝나면 그 안에서 상위 1% | 1.07% | 100 | 111 |
| 전날 상위 1% 점수로 즉시 판정 | 2.22% | 120 | 121 |

하루 단위로 잘라도 대표 숫자는 거의 그대로임(111 → 106건, 짝지은 부트스트랩 차이 95% 구간 −2 ~ +13건). 반대로 제품이 나오자마자 판정하려고 문턱값을 미리 정해 두면, 순위 품질은 같은데(같은 물량이면 121건) 검사 물량이 평균 2.2%로 늘고 날마다 크게 흔들림(100대 이상인 날 기준 상위 10% 지점 4.2%, 최대 34%). 그래서 권하는 운영은 "하루 마감 후 그날 생산분에서 상위 1%"이고, 즉시 판정은 물량 상한 같은 별도 장치가 필요함(실험하지 않음). 데이터의 시간 단위는 적혀 있지 않아 제품 수의 자기상관(2.4단위·16.8단위)으로 하루·1주를 추정했음 `[추정]`. 자세한 조건은 `MODEL_CARD.md` 3절 ③.

**④ 예측을 앞당기면 — 완만한 곡선이 아니라 절벽**

| 예측 시점 | 포함 공정 | Lift@1% |
|---|---|---|
| 첫 공정 직후 | 8 / 52 | 0.5 |
| 전반부 | 26 / 52 | 1.1 (무작위 수준) |
| 중반 | 47 / 52 | 11.3 |
| 전 공정 | 52 / 52 | 10.8 |

공정 26개까지는 예측이 안 되고 47개에서 전체 성능에 도달함. 조기 개입 여지가 거의 없어 이 모델의 쓸모는 검사 우선순위에 한정됨.

**⑤ 신호가 두 곳에 겹쳐 있음 — SHAP 순위는 "꼭 필요한 곳"이 아님**

| 조건 (LightGBM 재학습) | 포착 건수 | 전체 대비 |
|---|---|---|
| 전체 | 111 | — |
| SHAP 상위 3개 공정(`L3_S33`·`S29`·`S30`) 제거 | 109 | −2 |
| 조기예측 절벽 구간 공정 21개 제거 | 92 | −19 |
| 제품 전체 여정 구조값(총 공정시간·경로 등 13개) 제거 | 109 | −2 |
| **둘 다 제거** | **10** | **−101 (무작위 수준)** |

구조값만 빼면 거의 그대로(−2건), 절벽 구간만 빼면 일부 줄고(−19건), 둘 다 빼야 무너짐(−101건). 한쪽이 빠지면 다른 쪽이 상당 부분 대신함. 조기예측 절벽도 이것으로 설명됨(초반에는 둘 다 없음). 그래서 공정 순위는 "모델이 판단할 때 본 곳"으로만 쓰고 "결정적 공정"이라고 하지 않음. 한 묶음씩만 빼 보면 "어느 쪽도 중요하지 않다"는 틀린 결론이 나옴.

**⑥ 시기에 따라 포착률이 흔들림 — 다만 "멀어질수록 못 잡는다"까지는 아님**

시험 구간을 시작 시각 순으로 시기 5개로 나눈 검사율 1% 포착률이 19.2% / 13.2% / 10.8% / 3.9% / 8.8%임. 마지막 시기에 다시 오르므로 학습 시점에서 멀어질수록 단조롭게 떨어진다고는 말할 수 없음. 시기별로 잡은 건수가 47 / 20 / 21 / 8 / 15건으로 작고 시기별 실제 검사율도 0.78~1.14%로 달라, 추세를 판단하기에는 근거가 약함. 시험 구간 전체 포착률조차 95% 구간이 8.6~15.4%로 넓어, 시험 구간 하나로 재학습 주기별 차이를 가리기 어렵다고 보고 재학습 주기 실험은 하지 않기로 함.

처음에는 잡은 불량 111건의 시기별 **비중**(시기1 42.3% / 시기4 7.2%)만 보고 "재학습 주기를 짧게"라고 적었음. 비중은 그 시기에 불량이 몇 건 있었는지에 따라 달라지므로 "그 시기를 못 잡았다"는 뜻이 아님. 포착률로 다시 계산해 고침. 놓친 불량과 잡은 불량은 공정 구조(방문 공정 수·측정값 개수·공정시간)로는 구별되지 않았고, 잡은 불량의 99.1%가 드문 경로 제품이었음.

### 발견

**① 결측 = 미방문 가설이 증거로 확인됨** — Week 1의 핵심 산출물

제품마다 "숫자가 전부 결측인 공정"과 "날짜가 전부 결측인 공정"을 비교함. **59,187,350칸 중 불일치가 3칸**(일치율 99.99999%). 불일치는 `L0_S22` 2칸, `L0_S9` 1칸이고 모두 "숫자만 결측"(= 지났지만 측정 안 함) 유형. "날짜만 결측"은 0건.

→ 결측을 평균으로 채우는 것은 틀린 처리임. **"어느 공정을 지났나"가 그 자체로 정보**임. 공정 칸 기준 75.7%가 미방문임.

**② Id 순서 누설이 실재함** — 수치로 확인

| | 값 |
|---|---|
| 전체 불량률 | 0.581% |
| 앞 제품(Id순)이 불량일 때 불량률 | **5.45%** |
| **배수** | **9.38배** |
| Id ↔ 시작시각 순위상관 | **0.002** (거의 0) |

Id는 시간순이 **아닌데도** 인접 Id 제품의 정답이 9.4배 상관됨. 운영에서는 얻을 수 없는 정보이므로 배제 대상이고, Week 2에서 일부러 넣어 성능이 얼마나 부풀려지는지 수치로 남길 것임.

**③ ⚠️ 시간 구간별 불량률이 크게 다름**

| 구간(시작 시각 순 5등분) | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|
| 불량률 | 0.604% | 0.755% | **0.831%** | **0.308%** | 0.407% |

구간 3과 4 사이에 **2.7배** 차이. 앞 60% 학습 / 뒤 20% 시험으로 나누면 두 기간 불량률이 약 1.8배 다름. → **고정 확률 임계값을 쓰면 실제 검사 물량이 목표를 벗어남.** 설계 10절(임계값 안정성, 고정 임계값 vs 이동 분위수)을 "시간 남으면"에서 **필수로 올려야 함**.

**④ 컬럼명의 라인 번호는 공정 순서가 아님**

제품 안에서의 상대 시각으로 공정 순서를 추정한 결과, L0·L1이 먼저고 **L2(S26·S27·S28)가 가장 마지막**임.

**⑤ 경로가 뭉쳐 있고 경로별 불량률이 다름**

상위 20개 경로가 전체의 **29.6%**를 덮음. 주된 갈래는 8공정짜리와 13공정짜리 두 가지. 경로별 불량률 차이가 큼 — `L1_S24` 갈래 **0.675%** vs `L1_S25` 갈래 **0.34%**로 약 2배.

**⑥ 측정값이 두 공정에 쏠려 있음**

`L1_S25` 284개, `L1_S24` 229개로 **두 공정이 968개 중 513개(53%)**. 공정별 측정값 수는 최소 1 / 중앙값 8 / 최대 284. → 설계 9절의 "공정 단위 집계 교란" 우려가 극단적으로 실재함. **단순 합계로 집계하면 이 두 공정이 무조건 1·2위를 차지함.** 3방식 병기가 필수임이 확인됨.

### 실제 데이터를 돌려서 고친 결함

**공정 순서 추정이 교란돼 있었음.** 공정별 **절대** 날짜 중앙값으로 순서를 정했는데, 그러면 "그 공정을 지난 제품이 언제 생산됐나"가 순서로 잘못 읽힘.

- `L3_S31` — 제품의 **3.29%만** 지나고 그 제품이 전부 생산 초기(날짜 24~179)에 몰려 있어 순서 **1번**으로 올라왔음
- `L3_S46` — 방문 제품이 **단 1명**인데 순서 **2번**으로 올라왔음
- 둘 다 지난 38,957명만 보면 `L3_S31`과 `L3_S29`의 날짜 중앙값이 **똑같이 112.1** → 순서가 아니라 생산 시기였음

**제품 안에서의 상대 시각**(공정 날짜 − 그 제품 자신의 시작 시각)으로 바꾸고, 방문 제품 수와 순서 신뢰 표시를 함께 냄. 이 결함을 재현하는 회귀 테스트를 추가해, 옛 방식으로 되돌리면 실패하는 것까지 확인했음.

### 검증을 어디까지 했나

테스트 **117개** 통과(`tests/`, 2026-10-20 shap 을 뺀 `requirements.txt` 로 만든 새 가상환경 기준). 통과만으로는 믿을 수 없어서 **일부러 코드를 망가뜨려 테스트가 죽는지 확인**했음. 아래 표는 Week 0~1 분이고, Week 2~4 모듈도 같은 방식으로 확인했음(누설 경로 차단 · Lift 를 실제 검사율로 나누는지 · 조기예측 시점별 입력 재계산 · 겹친 신호 재현 등).

| 일부러 넣은 오류 | 잡혔나 |
|---|---|
| `dtype` 고정 제거 (float32 다운캐스트·스키마 고정이 사라짐) | 예, 2개 실패 |
| 행 수에서 헤더를 빼지 않음 (off-by-one) | 예, 4개 실패 |
| 컬럼명 정규식에서 날짜(`D`)를 빼먹음 | 예, 1개 실패 |
| 공정 전부결측 판정을 `all` → `any` 로 바꿈 | **처음엔 안 잡힘 → 테스트 보강 후 잡힘** |
| 결측 불일치 두 종류(숫자만/날짜만)를 뒤바꿈 | 예, 2개 실패 |
| 경로 비트키 가중치를 전부 1로 (다른 경로가 같은 키가 됨) | 예, 1개 실패 |
| 시간 분할 전 정렬을 빼먹음 | 예, 1개 실패 |
| 공정 63개 초과 안전장치 제거 | 예, 1개 실패 |
| 공정 순서를 상대시각 대신 **절대날짜**로 되돌림 | 예, 1개 실패 — **실제 데이터에서 발견한 결함의 회귀 테스트** |

**`all` → `any` 변형이 처음에 안 잡힌 것이 이번에 얻은 것임.** 합성 데이터가 한 공정의 컬럼을 늘 한꺼번에 비워서 둘의 차이를 건드리지 못했음. 실제 공정에서는 측정 항목 몇 개만 누락될 수 있고, 그때 `any`를 쓰면 그 제품이 공정을 지나지 않은 것으로 잘못 세게 됨. 일부만 비는 경우를 넣은 테스트를 추가해 막았음.

**테스트 통과는 "정해 둔 정답을 계산이 되찾는다"는 뜻일 뿐이고, "Bosch 원본에서 맞다"는 뜻이 아님.** 실제로 원본을 돌려 보니 합성 데이터로는 못 잡은 결함이 하나 나왔음(위 "고친 결함"). 그래서 **합성 데이터 테스트와 실제 데이터 실행은 둘 다 필요함.**

변환에서 특히 노린 것은 **"어떤 컬럼이 앞 조각에서는 전부 결측이고 뒤 조각에서는 값이 있는"** 경우임. Bosch는 결측이 80%를 넘어서 실제로 자주 일어나고, dtype을 미리 못 박지 않으면 조각별 스키마가 흔들려 변환이 깨지거나 값이 조용히 바뀜.
